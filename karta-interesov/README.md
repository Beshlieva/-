# Карта интересов — профориентационный тест (frontend)

Веб-приложение для прохождения теста «Карта интересов» (методика А.Е. Голомштока, адаптированная версия):
**174 утверждения → 29 направлений**. Для каждого утверждения выбирается один из пяти вариантов
(«Очень нравится» … «Очень не нравится»), в конце показывается карта интересов: топ-5, «роза» по всем направлениям и список.

**Технологии:** React 19 · TypeScript · Vite · Tailwind CSS 4.

Проект создан в Figma Make и подготовлен к локальной работе в Visual Studio Code.
Сервера и базы данных пока нет — подготовлен слой для их будущего подключения (см. раздел 9).

---

## 1. Что нужно установить

1. **Node.js 22 LTS** — скачайте установщик с <https://nodejs.org> (кнопка «LTS») и установите, соглашаясь со всеми
   вариантами по умолчанию. Подойдёт любая версия **20.19+ или 22.12+**.
2. **Visual Studio Code** — <https://code.visualstudio.com>.
3. *(необязательно)* **Git** — <https://git-scm.com>, понадобится позже для хранения истории изменений.

Проверьте установку: откройте терминал (Windows — «Командная строка» или PowerShell, macOS — «Терминал») и выполните

```bash
node -v
npm -v
```

Обе команды должны вывести номера версий (для `node` — не ниже `v20.19.0` / `v22.12.0`).
Если терминал пишет, что команда не найдена, перезапустите компьютер или VS Code и проверьте ещё раз.

например `Документы/karta-interesov`. Путь лучше выбирать без экзотических символов.
После распаковки внутри папки должны лежать `package.json`, `index.html`, папки `src`, `docs` и другие файлы.

## 5. Установка зависимостей

```bash
npm install
```

Команда скачает библиотеки в папку `node_modules` (нужен интернет, 1–3 минуты). Папка большая и в архив не входит —
она каждый раз восстанавливается этой командой. После установки появится файл `package-lock.json` —
оставьте его, он фиксирует версии библиотек.


Откройте в браузере **<http://localhost:5173>**. Изменения в файлах `src/` применяются сразу, без перезагрузки.

Готовый сайт появится в папке `dist/`. Посмотреть его так, как он будет работать на хостинге:

## 8. Как проверить, что всё работает

Выполните по порядку:

```bash
npm run verify      # данные (174 вопроса, 29 категорий, формула) и логика таймера/пропусков — без браузера
npm run typecheck   # проверка типов TypeScript — должна завершиться без ошибок
npm run build       # production-сборка — должна завершиться словами "built in …"
```

Затем запустите `npm run dev` и пройдите вручную (держите открытой консоль браузера, F12 → Console: красных ошибок быть не должно):

1. Главная → «Начать тест» → инструкция → «Начать тест»: открывается вопрос 1, таймер показывает 15 и идёт вниз.
2. При остатке 5 секунд и меньше таймер становится красным; на нуле вопрос пропускается, открывается следующий, сверху появляется плашка «Время вышло».
3. Клавиши **1–5** отвечают на текущий вопрос (1 — «Очень нравится» … 5 — «Очень не нравится»); повторное быстрое нажатие второй ответ не создаёт.
4. Обновите страницу (F5) посреди вопроса: время **не сбрасывается**, остаток продолжается; если за время отсутствия оно истекло — вопрос пропущен.
5. После 174-го вопроса — «Показать результат». Если есть пропуски, показано их количество и кнопка «Пройти пропущенные вопросы»; результат без ответов на все вопросы не открывается.
6. Повторный круг показывает только пропущенные; если время снова вышло, вопрос остаётся пропущенным и круг можно повторить.
7. Когда отвечены все 174 вопроса, «Показать результат» открывает карту интересов («Топ‑5», «Роза», «Список», клик по направлению открывает карточку 0–100).
8. «Пройти тест заново» (с подтверждением) очищает локальные данные и возвращает на главную.

> Чтобы быстро проверить конец теста, не нужно отвечать вручную 174 раза: можно пропускать вопросы, дожидаясь таймера, или выбирать ответы клавишами.

## 10. Подключение backend (PHP + MySQL)

Браузер **не должен** подключаться к MySQL напрямую: frontend общается с сервером по HTTP (JSON), а сервер — с базой.
Весь код, который обращается к серверу, собран в `src/services/api/`; экраны об HTTP ничего не знают.

### Режимы работы

| Режим | Значение | Что происходит |
|---|---|---|
| Реальный API (по умолчанию) | `VITE_API_MODE=api` | Регистрация → серверная попытка → ответы по одному → результат рассчитывается и сохраняется в MySQL. Таймер ведёт сервер; персональные данные и результаты хранятся в базе. |
| Демо | `VITE_API_MODE=demo` | Локальная проверка без сервера. Регистрация, сохранение на сервере и админская аналитика недоступны. |

### Локальный запуск API и базы данных

1. Установите PHP 8.2+ с `pdo_mysql` и MySQL 8 (например, XAMPP).
2. Выполните шаги 1–5 из [backend/README.md](backend/README.md): настройте `backend/.env`, запустите `php bin/init-db.php`,
   создайте администратора через `php bin/create-admin.php --username=admin` и запустите API на `localhost:8000`.
3. В корне frontend скопируйте `.env.example` в `.env.local`. По умолчанию уже заданы `VITE_API_MODE=api` и
   `VITE_API_BASE_URL=http://localhost:8000/api/v1`.
4. Запустите или перезапустите `npm run dev`. Проверьте backend по адресу `http://localhost:8000/api/v1/health`.

> ⚠️ Всё, что начинается с `VITE_`, попадает в публичный код сайта. **Не записывайте в эти переменные пароли,
> токены и ключи.** Доступ к MySQL, секреты и проверка прав администратора — только на стороне сервера.

Если сервер на другом адресе (домене/порту), он должен разрешить запросы с адреса frontend (заголовки CORS).
Если не хотите настраивать CORS на этапе разработки, можно проксировать `/api` через Vite (опция `server.proxy` в `vite.config.ts`)
и указать `VITE_API_BASE_URL=/api/v1`.

Backend PHP + MySQL уже находится в папке `backend/`; он реализует следующие адреса:

Подробно, с примерами JSON, — в **[docs/API_CONTRACT.md](docs/API_CONTRACT.md)**. Кратко:

| Адрес | Назначение |
|---|---|
| `POST /attempts` | принять ответы, сохранить, **пересчитать баллы на сервере**, вернуть результат |
| `GET /attempts/{id}/result` | вернуть сохранённый результат |
| `GET /admin/analytics/summary` | сводная статистика (только администратор) |
| `GET /admin/analytics/regions` | статистика по регионам Казахстана (только администратор) |
| `GET /admin/attempts` | список прохождений (только администратор, без персональных данных) |
| `GET /admin/analytics/overview` | зарегистрированные, начатые и завершённые попытки, участники по регионам (только администратор) |
| `GET /admin/users` | участники: имя, email, возраст, регион, дата регистрации; поиск `q`, фильтры `regionCode`, `dateFrom`, `dateTo` (только администратор) |
| `GET /admin/results` | завершённые тесты с данными участника, те же фильтры (только администратор) |
| `GET /admin/results/{id}` | полный результат конкретного теста (только администратор) |
| `GET /admin/export/results.csv` | экспорт результатов в CSV (UTF-8 с BOM, разделитель `;`), те же фильтры (только администратор) |

### Входы и панель администратора

В верхнем углу стартовой страницы есть отдельные ссылки для участника и администратора. Пользователь регистрируется
и входит по email; администратор входит на `/#/admin`. Публичную саморегистрацию администраторов намеренно не добавляли:
создать админскую учётную запись может только владелец сервера командой `php bin/create-admin.php --username=<логин>`.
Пароль администратора вводится в консоли и в БД хранится только в виде хэша. Токены участника и администратора
проверяются сервером независимо.

Панель показывает статистику по зарегистрированным участникам и завершённым тестам, фильтры по региону и периоду,
результаты участников, экспорт CSV, популярные направления и таблицу «Самое сильное направление в каждом регионе».
В последней для каждого региона выводится ровно одна профессия с максимальным средним результатом среди завершённых
тестов, в процентах от шкалы 0–100.

Вопросы и направления для заполнения таблиц MySQL — в `docs/data/questions.json` и `docs/data/categories.json`.

### Регистрация и проверка данных (frontend + backend)

1. Поднимите backend по `backend/README.md` (шаги 1–5; для существующей БД — `php bin/migrate.php`).
2. В `.env.local` во frontend: `VITE_API_MODE=api`, `VITE_API_BASE_URL=http://localhost:8000/api/v1`; перезапустите `npm run dev`.
3. Нажмите в верхнем углу «Вход / регистрация участника» или «Начать тест». Пользователь появится в таблице `users`
   (phpMyAdmin → `karta_interesov` → `users`).
4. Повторная регистрация с тем же email покажет сообщение и ссылку «Перейти ко входу».

## 11. Поведение режимов

**В режиме API (PHP + MySQL):**

- регистрация и вход участника; учётная запись хранится в MySQL, пароль сохраняется только как безопасный хэш;
- ответы и таймер хранятся на сервере, результаты рассчитывает backend и сохраняет в MySQL;
- админская панель со статистикой по регионам, включая единственное самое сильное направление и его средний процент;
- фильтрация по региону и периоду, просмотр результатов и экспорт CSV.
- в таблице по регионам показано ровно одно ведущее направление — по самому высокому среднему проценту завершённых тестов.

**Демо-режим без сервера:** тест и локальный черновик проходят в браузере; для долговременного хранения и админского анализа
нужно запустить MySQL и API. Запуск в режиме API без доступного сервера покажет ошибку соединения; результат не выдаётся
за сохранённый, если backend не подтвердил запись.


## 12. Частые проблемы

| Проблема | Решение |
|---|---|
| `npm` / `node` не найдены | Установите Node.js (раздел 1), перезапустите VS Code |
| `Unsupported engine` / ошибка при `npm install` | Обновите Node.js до 22 LTS |
| Порт 5173 занят | Закройте другой запуск проекта или выполните `npm run dev -- --port 3000` |
| Белый экран | Откройте консоль браузера (F12 → Console) и пришлите текст ошибки |
| Шрифты выглядят иначе | Шрифты Source Serif 4 и Golos Text подгружаются с Google Fonts — нужен интернет; без него используются системные |
| Хочу начать тест с нуля | Кнопка «Пройти тест заново» или F12 → Application → Local Storage → удалить ключ `karta-interesov:local:session:v2` |

  из проекта убраны: вне Figma они не нужны, а `.gitattributes` ломает работу с Git без установленного Git LFS.
- **Этап 1 (frontend).** Таймер, повторное прохождение пропусков, обновлённый дизайн. Вернуться к предыдущему вопросу нельзя —
  иначе ограничение времени можно обойти. Прогресс старой версии (ключ `…progress:v1`, без таймера) не переносится.
  Данные теста (`src/data/questions.ts`, `docs/data/*.json`) не менялись. Backend и аналитика на этом этапе не добавлялись.
- **Этап 2 (backend).** Добавлены `backend/` (PHP 8.2 + PDO, REST API, миграции MySQL, загрузчик справочников, серверный
  таймер, административная аналитика) и `docs/API_V2.md`. Инструкция по созданию БД и запуску API — `backend/README.md`.
  Frontend не менялся, кроме скриптов `npm run catalog:export` / `catalog:check` (синхронизация справочников с `docs/data/*.json`).
  *(Тест в режиме `api` переведён на этот поток на этапе 4.)*
- **Этап 3 (регистрация).** Экран `AuthScreen`: регистрация (имя, фамилия, email, возраст, регион из `src/data/regions.ts`,
  пароль) и вход по email + паролю. Backend: `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`,
  миграция `004_user_registration.sql` (возраст, хэш пароля, счётчик неудачных входов). Имя и фамилия хранятся в
  существующем `users.display_name`, регион — в `users.region_id`. После регистрации/входа `userId` и токен сохраняются
  в `localStorage` (`karta-interesov:auth:v1`) и подставляются в запросы (`Authorization: Bearer …`, `services/api/http.ts`).
  Пароль нужен для входа, поэтому в форму добавлены «Пароль» и «Повторите пароль» (в исходном списке полей их не было).
  Повторный email не создаёт дубликат и не даёт доступа к чужой учётной записи — показывается предложение войти.
  **В режиме `api` кнопка «Начать тест» ведёт через регистрацию/вход; в режиме `demo` (сервера нет) экран пропускается.**
  Тест, таймер и подсчёт результатов не менялись. Сам тест в режиме `api` на этом этапе ещё вызывал старый пакетный
  `POST /attempts` — исправлено на этапе 4.
  Панель администратора не добавлялась.
- **Этап 4 (тест через сервер).** В режиме `api` тест идёт по серверным методам из `docs/API_V2.md`:
  `POST /attempts` (создаёт попытку, открывает вопрос 1) → `POST /attempts/{id}/answers` (по одному ответу) →
  `POST /attempts/{id}/skips` (когда вышло 15 с) → `POST /attempts/{id}/retry-round` (пропущенные) →
  `POST /attempts/{id}/finish` (баллы считает и сохраняет сервер). Старая пакетная отправка и ошибка
  `BATCH_SUBMIT_NOT_SUPPORTED` больше не возникают: `testService.submitAttempt` в режиме `api` отключён.
  Код: `src/services/api/attemptService.ts` (HTTP-клиент попыток), `src/lib/serverAttempt.ts` (клиент серверной попытки),
  `src/lib/testView.ts` + `TestScreen` (общий экран вопроса для обоих режимов), `src/lib/attemptRef.ts`.
  - **Таймер.** Ровно 15 с на вопрос. Время открытия вопроса фиксирует сервер; браузер показывает остаток от `remainingMs`
    (с поправкой на задержку сети), краснеет на последних 5 с и по нулю отправляет пропуск. Просроченный ответ браузер не
    отправляет, а сервер отклоняет (`TIME_EXPIRED`). Повторный запрос и обновление страницы время вопроса не продлевают.
  - **Обновление страницы.** Приложение читает с сервера `GET /attempts/{id}` (или `/attempts/active`) и открывает тот же вопрос
    с оставшимся временем; ответы не теряются и не дублируются. В `localStorage` лежит только id попытки
    (`karta-interesov:attempt-ref:v1`) — ни ответов, ни баллов, ни времени.
  - **Без регистрации.** «Начать тест» ведёт на экран регистрации/входа; без токена серверную попытку создать нельзя.
  - **Демо-режим** (`VITE_API_MODE=demo`) работает как раньше: локальный движок и расчёт в браузере, ничего не сохраняется.
  - Проверки: `npm run verify` (данные, формулы, локальный движок, регистрация) и `npm run verify:server`
    (клиент серверного потока на имитации сервера). **Реальные PHP и MySQL в среде подготовки не запускались.**
- **Этап 5 (MySQL и админ-аналитика).** Режим API включён по умолчанию и указывает на локальный PHP backend.
  На стартовом экране в верхнем углу доступны вход участника и администратора. Админская учётная запись создаётся
  только владельцем сервера через `backend/bin/create-admin.php`; публичная регистрация администраторов не предоставляется.
  В панели используется `/admin/analytics/regions`: для каждого региона выбирается направление с максимальным средним
  процентным баллом среди завершённых попыток.
